# goit-algo-hw-09

Greedy algorithms and dynamic programming

Якщо номінали монет канонічні (тобто побудовані "розумно", наприклад: 1, 2, 5, 10, 25, 50), жадібний алгоритм часто повертає оптимальний розв'язок — мінімальну кількість монет для заданої суми.
Наприклад:
Сума: 63
Монети: [50, 10, 1]
Жадібний алгоритм: 1×50 + 1×10 + 3×1 = 5 монет — це оптимально.

Жадібний підхід може дати неправильний (неоптимальний) результат, якщо набір монет неканонічний.
Приклад:
Монети: [1, 3, 4]
Сума: 6
Жадібний алгоритм:
Візьме одну 4 (залишається 2)
Потім дві 1 → 3 монети
Оптимальний розв'язок:
Дві монети по 3 → 2 монети
Жадібний алгоритм не "дивиться в майбутнє", він обирає найбільшу монету, яка "поміщається", не оцінюючи, як це вплине на загальний результат.

## Порівняння жадібного алгоритму та алгоритму динамічного програмування

### Часова складність

- Жадібний: O(N)
- Динамічний: O(A × N)

### Продуктивність

Для "стандартного набору монет" (1, 2, 5, 10, 25, 50):

{50: 2, 10: 1, 2: 1, 1: 1}
Greedy time: 0.00010609626770019531
{1: 1, 2: 1, 10: 1, 50: 2}
Dynamic time: 0.00010609626770019531

- Обидва алгоритми дають однаковий (оптимальний) результат
- Час виконання практично однаковий навіть на великих сумах

### Висновок:

Жадібний підхід швидший і простіший, підходить для валютних систем із стандартними номіналами. Динамічне програмування — універсальніше, завжди знаходить мінімальну кількість монет, але працює повільніше на великих сумах і множині номіналів.
